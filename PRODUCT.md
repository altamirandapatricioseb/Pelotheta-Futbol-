# Product

## Register

product

## Platform

web

## Users

Primary: recruiters and interviewers for Data Analyst / Sports Data Analyst roles who open the live URL from a portfolio and judge in minutes whether the owner can turn raw football data into trustworthy analysis. Secondary: Boca Juniors fans and analysts who want season numbers for players and team with clear sources.

## Product Purpose

Pelotheta Θ is a data analysis system for Boca Juniors (men's first team, 2026 season): scraped from free, permitted sources, validated, calculated in a Python + SQL pipeline and shown in six interfaces (Gráficos, Equipo, Jugadores, Situaciones, Comparar, Actualizar). Success: every number has a source, a level (A direct, B calculated, C not available) and an explanation; nothing is invented.

## Positioning

A broadcast-grade football stats room built from scratch on free data, where every figure can be traced back to how it was calculated.

## Brand Personality

Precise, broadcast, confident. Spanish (Argentina) voice, direct and explanatory, no hype. Numbers first; motion that feels like a TV graphics package, never like a toy dashboard.

## Anti-references

Generic SaaS admin templates, "toy dashboard" card grids, betting sites (no odds shown), violet except the two allowed secondary violets (#734f9a, #965fd4, always next to green), emojis.

## Design Principles

1. Every number earns trust: source, level and formula one step away.
2. Show the gap honestly: `n/d` is visible, never hidden or filled.
3. Broadcast clarity: tabular numerals, strong hierarchy, green signal (#64cc4f) on layered green-tinted surfaces; best value in green, worst in red, always with a text label.
4. Motion conveys state and entrance (cascades, sliding selection), always smooth.
5. Explainable in an interview: simple structures over clever ones.

## Accessibility & Inclusion

WCAG 2.2 AA: keyboard navigation of tables (grid role, arrows), visible focus, contrast checked in light and layered dark themes (toggle in the header, saved in a cookie), win/draw/loss never by color alone. The owner chose always-on animations with an in-app switch to reduce them (section 9.10), instead of following prefers-reduced-motion.
